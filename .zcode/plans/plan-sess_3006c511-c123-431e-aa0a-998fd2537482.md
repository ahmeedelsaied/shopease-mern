### What changed since the last plan
The Vite proxy must **rewrite** `/sitemap.xml` and `/robots.txt` (root) to the backend's `/api/*` paths (via the existing `http://localhost:5000` target), so both origins serve the same backend-generated file without a second copy. Everything else matches the previous plan.

### Files to CREATE (backend — public, no auth)
1. **`backend/controllers/seoController.js`** — `getSitemap` + `getRobots` (asyncHandler-wrapped). Reads `PUBLIC_SITE_URL` (env, fallback `http://localhost:5173`, trailing slash stripped). Sitemap emits real home + real category-filter URLs (`/?category=<encoded>`, weekly, 0.6) + real product URLs (`/products/:_id`, lastmod = `updatedAt` when present, weekly, 0.7). `robots.txt` replicates the existing `Disallow` list and emits `Sitemap: <origin>/sitemap.xml`. XML special chars escaped; empty catalog returns a valid minimal `<urlset>`; no fake lastmod/IDs.

2. **`backend/routes/seoRoutes.js`** — `GET /sitemap.xml` → `getSitemap`; `GET /robots.txt` → `getRobots`. Public (no `protect`/`admin`).

3. **`frontend/src/seo/websiteJsonLd.js`** — pure `buildWebsiteJsonLd({ siteUrl })` (Schema.org `WebSite` + minimal `Organization`, real name/description/url, no invented logo/social) and `buildBreadcrumbJsonLd({ siteUrl, items })` for ProductDetails (Home → category → product, paths resolved against `siteUrl`).

### Files to MODIFY (backend)
4. **`backend/server.js`** — `import seoRoutes` + `app.use('/api', seoRoutes)` (mounted before errorHandler, after other `/api/*` mounts). No auth change.

5. **`backend/.env`** and **`backend/.env.example`** — add `PUBLIC_SITE_URL=http://localhost:5173` (mirrors `VITE_SITE_URL` default; no production domain invented).

### Files to MODIFY (frontend)
6. **`frontend/vite.config.js`** — extend the dev proxy so `/sitemap.xml` and `/robots.txt` map to the backend's `/api/*` paths on `http://localhost:5000` with `changeOrigin: true` (root paths → rewrote to `/api/sitemap.xml` and `/api/robots.txt`). Keeps the existing `/api` proxy intact.

7. **`frontend/public/robots.txt`** — replace the static stub with a minimal fallback (`Allow: /` + `Sitemap: /sitemap.xml` + the same `Disallow` list) so the static fallback that ships in the built bundle stays consistent with the backend-generated one. Comment points to the backend as canonical when the proxy/reverse proxy is present.

8. **`frontend/public/sitemap.xml`** — **delete** the stub (replaced by the backend-generated file served via the proxy at the root).

9. **`frontend/.env.example`** — add a short note that the backend sitemap reads `PUBLIC_SITE_URL`; in production both `VITE_SITE_URL` (frontend) and `PUBLIC_SITE_URL` (backend) should point to the same origin.

10. **`frontend/src/pages/HomePage.jsx`** — feed `buildWebsiteJsonLd({ siteUrl })` into the existing `<SEO>` `jsonLd` prop (reuse `DEFAULT_SEO.description` and `getSiteUrl()`; no new fetch, no invented data).

11. **`frontend/src/pages/ProductDetails.jsx`** — feed `buildBreadcrumbJsonLd({ siteUrl, items: [{Home}, {category}, {product.name}] })` into the existing `<SEO>` `jsonLd` prop alongside the existing product JSON-LD (the `<SEO>` component already supports a single object; the two graphs will be combined into a `@graph` array inside `websiteJsonLd.js`'s caller composition). `category` and `name` come from the already-loaded product state (no extra fetch).

### NOT changed (per constraints)
- `components/SEO.jsx`, all auth/admin middleware, Cart, Checkout, Orders, admin pages, dashboard charts, the design system, routing, Tailwind. No new npm dependency.
